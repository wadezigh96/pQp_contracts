# QPC Zcash Agent Adapter

Fail-closed Zcash adapter boundary for QPC agentic payments.

## Implemented

- Official librustzcash `zcash_address` parser for ZIP-316 Unified Addresses.
- Mainnet/Testnet validation using `zcash_protocol` network types.
- Receiver capability extraction for Orchard, Sapling, and transparent pools.
- Bare non-Unified address rejection at the Unified Address boundary.
- Opaque recipient reference is supplied by the wallet boundary and is never derived from or equal to the raw UA.
- Existing shielded-only intent policy, expiry checks, replay guard, and receipt-gated lifecycle.

## Security boundary

The raw Unified Address must stay inside the wallet/adapter boundary. Never put it in NEAR contract state, public events, agent prompts, route logs, or CI output. A random opaque reference should be generated by the wallet boundary; do not use a deterministic hash of the address.

## Not implemented yet

This crate does not create wallet keys, derive addresses, sync notes, construct or sign transactions, broadcast to Zcash testnet, inspect confirmations, or verify shielded receipts. Those remain separate wallet/backend integration tasks. Do not send funds based on this prototype.

Zcash consensus validity must be checked by a consensus node; address parsing or provider callbacks do not prove transaction consensus validity.
